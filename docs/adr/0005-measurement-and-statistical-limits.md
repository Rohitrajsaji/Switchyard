# ADR 0005: event-time measurement and statistical limits

Status: accepted M4 SQL measurement. Incremental aggregates and guardrail execution follow in M7/M9.

Results read a repeatable-read PostgreSQL snapshot. Each run/user contributes one denominator entry: the earliest accepted event-time exposure, with event-ID byte order breaking ties. Completion requires an accepted referenced exposure matching run/user/variant and must occur after that display, within thirty minutes of the earliest exposure. Completion is an existence predicate, so extra event IDs cannot inflate a user's conversion. Accepted outcomes with missing references remain pending; invalid references and out-of-window completions are reported separately. Future facts wait for event time. Targeting and quarantined facts are excluded.

MVP derives contributions directly from raw SQL, so arrival of an earlier exposure can add or subtract conversion without mutable counters. Provisional and finalized cohorts are disjoint; total is their sum. Finalization requires strictly more than thirty minutes plus twenty-four hours since exposure, preserving acceptance at the inclusive late deadline. A new run or current flag edit never moves historical facts. M7 will reproduce this oracle with transactional per-user correction and preserve finalized summaries before raw retention cleanup.

Conversion rates use [NIST's Wilson interval](https://www.itl.nist.gov/div898/handbook/prc/section2/prc241.htm). A pooled, two-sided [two-proportion test](https://itl.nist.gov/div898/software/dataplot/refman1/auxillar/binotest.htm) is descriptive; Switchyard requires at least five observed successes/failures per arm and five expected per cell under the null. Unsupported samples return insufficient data. A zero control rate has no relative lift. Pairwise comparisons are unadjusted; repeated viewing is not a valid sequential stopping rule.

Sample-ratio checks compare unique exposed-user counts with immutable weights using a chi-square test. Expected counts must reach five in every variant. The warning threshold is 0.0005, following the conservative example in [Microsoft's SRM guidance](https://www.microsoft.com/en-us/research/articles/diagnosing-sample-ratio-mismatch-in-a-b-testing/). Mismatches suppress comparison p-values while preserving descriptive counts/lifts. Up to ten variants need only integer degrees of freedom one through nine; finite even/half-integer survival recurrences avoid a statistics dependency. Tests check [NIST's critical-value table](https://www.itl.nist.gov/div898/handbook/eda/section3/eda3674.htm), published proportion examples and independently bisected Wilson score-test roots.

Product request metrics require a valid exposure reference. Error rate is failed requests divided by samples. Duration bins have upper bounds 50/100/250/500/1000/2500/5000/10000/60000 ms; returned p95 is the enclosing upper bound, not an exact percentile. These are listing-operation measurements, separate from Switchyard API latency. Empty samples produce null rates/percentiles. Safety policy will use fresh operational windows and finalized conversion cohorts, not these descriptive p-values.
