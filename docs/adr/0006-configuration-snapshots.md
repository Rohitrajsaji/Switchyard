# ADR 0006: Immutable snapshots with bounded authoritative age

Status: accepted; M6 coordinator and Docker failure drill verified locally.

## Decision

Cache a configuration per project/environment/flag key. Do not cache user assignments or put attributes/user identities into cache keys. `pkg/snapshot` is the shared wire/compilation boundary so future SDKs use the same version and expiry rules as the API.

Version 1 wraps an immutable definition and `verified_at`. Capture that timestamp **before** the authoritative PostgreSQL query; pool wait and query execution consume freshness instead of extending it. Only a successful authoritative read produces a new verification timestamp. Redis reads, intermediary responses and process restarts preserve it. Reject unknown versions/fields, trailing data, mismatched scope, invalid definitions and payloads above 1 MiB. Evaluate only while age is strictly below 30 seconds; reverify after two seconds. A timestamp ahead of the reader's clock is conservatively unusable until its clock reaches that timestamp. These rules assume bounded host clock skew; they do not create a distributed clock service.

Compile once, own every byte slice, and share immutable pointers between readers. Caller edits and returned JSON/value bytes cannot mutate the stored configuration. The coordinator replaces whole pointers, coalesces misses and repairs from PostgreSQL. Four fixed workers share a 64-job queue; admission is capped at 256 keys and a 32 MiB weight budget (wire size × 8 plus 2 KiB per snapshot, an accounting estimate rather than an RSS guarantee). No goroutine is started per miss. One polling goroutine checks every 250 ms and refreshes active keys at two-second intervals; keys unused for thirty seconds are not polled. Source reads have a one-second deadline. Request cancellation leaves shared work available to other readers; shutdown cancels workers and wakes queued readers. Failed reads retry after two seconds. PostgreSQL remains the authorization truth; Redis availability is not required for API startup or readiness.

Redis stores each envelope in one hash. One Lua script compares canonical integer-string revisions and atomically updates definition, verification metadata, payload and TTL. Comparing revisions as Lua floating-point numbers would lose increments above 2^53, so compare decimal length then lexical order. Older revisions cannot overwrite newer disables. Equal revisions may update their proof timestamp only with identical configuration and flag identity. Reusing an unchanged proof does not renew TTL. TTL is the remaining authoritative age, rounded down to milliseconds; readers independently enforce expiry even if network delay lets a Redis key live slightly longer. Redis eviction/deletion loses cache history, so a monotonic fence applies to the currently present entry, not across a total cache reset. Authoritative polling and age checks provide repair and bounded staleness after resets.

Use the pinned official [`go-redis` client](https://redis.io/docs/latest/develop/clients/go/) 9.22.0 with a four-connection cap, explicit subsecond pool/connect/read/write deadlines, context deadlines and automatic retries disabled. Experimental client-side caching/automatic pipelines are unnecessary for this design. Redis 8.10.2 is pinned to a verified multi-architecture image digest from the [official image catalog](https://github.com/docker-library/official-images/blob/master/library/redis). The local server runs as the Redis user, has a 128 MiB container limit, a 96 MiB eviction ceiling, no persistence and localhost-only port access. PostgreSQL owns durable state. `make up` enables the `cache` Compose profile. Direct Compose operation can omit Redis and retain PostgreSQL snapshot loading.

## Evidence and limits

Injected-clock snapshot tests verify exact two-/thirty-second boundaries, cache relay/restart without renewal, future-time rejection, immutable byte ownership, concurrent evaluation and kill-switch precedence. Real Redis integration checks delayed concurrent writes, >2^53 and maximum-int64 revisions, identity/scope conflicts, corruption rejection, deletion repair and remaining-age TTL using only test-owned keys.

Application evaluation uses the coordinator after PostgreSQL application-key authorization on every request. Management previews read PostgreSQL directly. Local committed configuration changes fence pending reads and force authoritative refresh; other instances reconcile by polling. Monotonic deadlines and sticky expiry prevent an expired snapshot from reviving after a clock rollback. Configuration expiry/outage returns HTTP 503 with the declared safe fallback, no experiment assignment, no-store and Retry-After: 1. A known flag rejects a mismatched fallback even during outage. Complete PostgreSQL outage prevents authorization; local SDK fallback is M8 work.

Race tests cover 100 readers sharing one miss, worker/queue/admission bounds, invalidation during a blocked read, cancellation, negative caching and proof timing. Real HTTP integration preserves scope/revocation and proves twenty evaluations share one configuration source read. The independent Docker API observer measured disable propagation 1.9616 s, source refresh during Redis outage 1.8988 s and fallback 28.6816 s after locking configuration reads (the proof was already partly aged). Redis deletion/restart repaired, readiness stayed healthy during Redis failure and revocation denied cached evaluation. These are single-fixture observations, not percentiles or throughput. [Raw drill evidence](../benchmarks/m6-cache-drill.json) is retained. Hit/miss/stale/source/failure/backpressure counters are emitted in periodic structured logs; Prometheus export follows in M10.
